## 当前能力及缺口

| 层级 | 当前能力 | 仍需解决 |
| --- | --- | --- |
| 文件 | 递归扫描、文件头/扩展名、大小、SHA-256、逐文件错误、JSON/Markdown、日志 | 每步耗时、运行标识、工具版本、完整性复核和可重跑阶段 |
| DWG/DXF | DXF 读取与恢复、审计；DWG 临时副本转换接口 | 转换器未安装；真实 DWG 转换保真尚未验证 |
| 2D 结构 | entity/layer/text/dimension/block/geometry 统计，布局/块文字 | 文字坐标、实例归属、递归块变换、图框分区、外参与字体状态 |
| 公差与尺寸 | 关键词候选、尺寸样式名称和覆盖文本 | 标称值原文、小数位、样式/单实体公差覆盖、一般公差规则及适用范围 |
| 3D | STEP 格式和声明计数 | 几何内核、单位/装配、拓扑有效性、体积与特征、PMI |
| 业务身份 | 当前主要为文件路径 | 零件、图号、版本、图框与 2D/3D 关联及人工确认 |

当前清单状态是 7 个 DWG `blocked`、6 个 STP `inspected`。`blocked` 是环境依赖缺失，不能解释为文件损坏或 AI 不适合解析；`inspected` 仅代表文本探查完成。

## 探查目标与范围

用有限、可追溯的样本回答四个问题：是否能读到结构化 CAD；公差等关键要求是否完整且能关联到零件；纯 2D 与有 3D 样本分别支持何种分析；进入工艺/成本估算还缺什么数据。

本阶段设计涵盖文件清单、转换检查、CAD 基础字段、少量分区与制造要求提取验证、可用性评估。3D 内核验证可作为后续子阶段按依赖情况开展。2D 自动生成完整 3D、Agent 编排、工艺生成、工时模型和自动核价不在本轮开发范围。

## 分阶段流程

| 阶段 | 输入与操作 | 输出 | 失败/复核处理 |
| --- | --- | --- | --- |
| A 文件登记 | 只读遍历 raw，核对头部、类型、哈希、大小；标记重复文件 | 文件级清单及 run_id | 不支持、链接、权限异常逐文件记录 |
| B DWG 转换验证 | 转换副本或接收客户独立导出的 DXF，保存工具版本和来源映射 | 派生 DXF、转换日志、图面抽查 | 转换器缺失记 blocked；失败记 error；不覆盖原图 |
| C 结构化提取 | 布局、图层、实体、块定义/实例、属性、尺寸样式、文字、外参状态 | 实体证据与结构统计 | 审计问题、乱码、缺外参保留，不默默忽略 |
| D 图框/零件分区 | 依据图框、属性、布局和空间位置生成候选，人工抽样标注 | 零件区域、身份候选、范围 | 多视图/重复图框不重复当零件；179 数量待核对 |
| E 制造要求探查 | 原文、尺寸小数位、一般/明确公差、材料、粗糙度、热处理 | 字段候选及来源证据 | 规则冲突、范围不明、缺字段标记 unknown/review_required |
| F 可选 3D 检查 | 先保留现有文本探查；有内核后验证读取、单位、拓扑、几何、PMI | 分层 3D 可用性结果 | 无 3D 不终止 2D 探查；不能由声明数推导有效性 |
| G 关联与变更样例 | 图号/版本/文件名/尺寸生成 2D/3D 候选，比较旧新图框与几何 | 对应候选、差异记录 | 同名不自动确认；无旧版图纸时注明无法验证变更 |
| H 报告与复核 | 按文件、零件、字段汇总成功/缺失/冲突，抽样对照图面 | 数据可用性与下一阶段建议 | 区分无法读取和语义无法确定，列出补数需求 |

解析恢复与几何修复应记录前后状态。原始哈希不变检查独立于单文件解析是否成功；即使失败也应执行完整性复核。当前代码的末尾哈希检查在解析抛异常时不会执行，后续完善时需要调整。

外部转换器建议有执行超时和隔离的工作目录，防止单文件挂起整个批次。后续实现时记录异常类型、阶段、原始错误和恢复措施；批次继续处理其余文件。

## 拟议数据组织及模块

沿用 `cad_inventory.json` 作为文件级入口；新增数据采用独立文件或明确升级 schema，保留与现有消费者的兼容性。建议组织如下（尚未创建）：

| 产物 | 内容 |
| --- | --- |
| data/converted/ | 派生 DXF 与源文件映射，不修改 data/raw |
| data/processed/runs/<run_id>/ | 单次运行元数据、工具版本、阶段状态、文件清单 |
| entities.jsonl | CAD 实体、坐标、布局/块路径、原始属性与源文件标识 |
| parts.json | 图框/零件区域与身份候选 |
| manufacturing_requirements.json | 尺寸、公差、技术要求、证据及确认状态 |
| cad_matches.json | 2D/3D 及旧/新版本对应候选与确认依据 |
| reports/ | 汇总报告、抽查结果与下一阶段建议 |

业务模块按职责在 `src/cad_inventory/` 中拆分为登记、转换、DXF 特征、分区、制造要求、STEP 探查、关联、质量评估、报告。`scripts/` 保持薄入口；当前不需要为了角色命名拆分成多个 Agent。

原始内容、规范化值、推断候选分开保存。所有字段值都能回溯到 source_hash、实体 handle、布局、坐标/区域及提取方法；派生字段记录所依赖的证据。块定义中的文字与块实例上的文字分别建模，不将未插入的定义文字当成图面制造要求。

### 一般公差字段示例（设计示例，不是已解析客户数据）

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| requirement_type | general_tolerance | 与明确尺寸公差区分 |
| raw_text | 两位小数 ±0.01 | 保留原文与显示精度 |
| condition | displayed_decimal_places = 2 | 需人工确认条件解释 |
| lower / upper | -0.01 / 0.01 | 单位未经确认则保持未知 |
| scope | part_region_candidate | 来源图框与适用范围必须可定位 |
| source | source_hash + handle + layout + region | 原始证据 |
| review_status | pending | 未确认前不自动用于核价 |

零件公差关系应区分明确公差、一般规则和未知状态；优先级及例外依据客户确认的规则执行，不凭示例猜测。PDF 的“90%”暂存为待定义业务阈值，不写入未经校准的自动放行逻辑。

## 抽样验证与阶段验收

1. 六对同名 DWG/STP：逐对验证真实身份、版本、单位和对应关系，不只依据文件名。
2. 多零件大图：人工选取不同图框、块结构、尺寸与一般公差情况，并核对整图零件总数。先验证小样提取方法，再覆盖全图；抽样不能证明全图完整。
3. 公差变更案例：取得旧/新文件后，对照确认绘图区相同、一般公差发生变化、适用范围正确；记录漏检和误报。只有一个案例时只做回归验证，不作为统计性准确率依据。
4. 针对乱码、炸开文字/尺寸、嵌图、外参缺失、损坏文件、无 3D、单位缺失和重复版本分别报告处理结果。
5. 关键字段与人工基准对照，统计字段精确率/召回率、分区准确性、待复核比例，以及文件读取/转换成功率。工时和成本误差留到获得历史标签后评估。

建议第一阶段验收要求：每个文件都有明确状态与失败原因；原始文件内容不变；关键字段有可定位证据；未知值不填默认公差或零成本；对大图和成对样本给出有依据的可用性结论与补数清单。准确率、批量时延与抽样规模应与客户确认，本次不自定承诺值。

## 实施次序

下一次实施先解决 DWG 转换依赖并完成真实图面核对，然后增加文字/尺寸证据和公差字段，再验证图框分区与版本关系。3D 内核分析按实际数据需求推进。只有在字段可用性及历史数据关联得到验证后，才设计工艺/工时估算试点。
